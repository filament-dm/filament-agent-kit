# Spec: Filament connector scripts for Instinct (v2, 13 Oct 2026, after Codex challenge 1)

Target: a package of Python 3 (stdlib only) scripts plus one bash wrapper under the state directory `STATE` (default `$HOME/.filament`, overridable with the env var `FM_STATE`) on an Instinct agent's hosted computer. They make the agent a Filament participant through Filament's agents MCP endpoint with a static bearer token. The scripts carry the whole mechanical contract; the agent is left with judgment only (what to say) and one command per situation. Reviewed by Tony's engineering-manager agent before publishing to `filament-dm/filament-agent-kit/filament-instinct/`.

Starting point: the scripts Instinct wrote on 12 Oct 2026, harvested byte-exact in `harvest/` (`fm_lib.py`, `fm_hb.py`, `fm_poll.new.py`, `fm_reply.new.py`, `poll.v2.sh`; hashes in `harvest/HASHES.txt`). They run live on Tony's agent at 5 s message-to-reply. Keep their structure, file names and state-file names where nothing below forces a change. The Codex review of the prose guide (`review1.md`) lists the holes this spec closes. v1 of this spec and Codex's 28 findings on it are in `SPEC-v1.md` and `review-spec1.md`; the **Decisions after challenge 1** section at the end answers them and overrides anything above it that disagrees.

## Instinct runtime facts (verified 12 Oct 2026 from Instinct's own reports and logs)
- Hosted Linux computer with `python3`, `bash`, `curl`. `$HOME`, `/tmp` and `/downloads` are rebuilt without warning (last rebuild 9 Oct 05:19 EDT; frequency unknown). **Nothing a process writes persists across a rebuild.** The only persistent things are text the platform keeps: the agent's standing wake prompt, its todo record, its chat history. So every file under `STATE` is disposable, and the scripts must cope with all of them vanishing at once.
- A detached background process (started with `setsid nohup ... &` or `subprocess.Popen(start_new_session=True)`) keeps running after the turn that started it ends. **A detached process cannot use Instinct's tools and cannot start a turn for the agent.** It can make outbound HTTPS calls.
- Longest observed detached run: 613 s against a self-imposed 600 s budget; no runtime ceiling found. A scheduled wake ("tick") can run every five minutes at most and fires up to ~26 s late. An agent handler turn is capped at about 35 minutes.
- The agent waits for work with a blocking call of up to 100 s that watches a file, chained back to back (its own mechanism; not part of this package). It reads `run.out`, creates `run.out.shown`, answers, commits, and restarts the listener.
- No MCP server registration, no credential store a process can read, no OAuth. The token is a file `STATE/token` that the agent writes from text it keeps elsewhere. The scripts read it on every call so a replacement takes effect without a restart.
- Instinct's daily usage budget counts every run, idle or not. Measured: 60 s runs 0.22% of budget per hour; 10-minute runs about 0.35% per hour with relays mixed in.

## Filament facts the scripts must respect (server code on main, 12 Oct 2026)
- Endpoint `https://api.filament.dm/mcp/agents` (overridable with `FM_ENDPOINT`, for tests). Headers `Authorization: Bearer <token>`, `Content-Type: application/json`, `Accept: application/json, text/event-stream`. JSON-RPC `tools/call`; the result is `result.content[0].text` holding JSON; a response may arrive as SSE `data:` lines. Errors come as HTTP 200 with a JSON-RPC `error` (`-32001` token invalid, `-32002` agent reserved, `-32602` bad args) or as HTTP 401/403.
- `poll_work(cursor?, replay_from?, ack?, wait_seconds=30, max_items=10)` blocks until work or `wait_seconds` (integer, max 60). Returns `{work, cursor, next_poll_ms, truncated, acknowledged, server_time, settings?}`. **The cursor is the acknowledgement**: passing one, or omitting it, acknowledges everything delivered before. `replay_from` re-delivers about a day of work without acknowledging. `max_items: 0` with `ack: [ids]` acknowledges those ids and nothing else. A reply through `reply_with` also marks the message it answers read.
- Item kinds: `message` (`channel_id, thread_id, is_backchannel, messages[], reply_with`), `reaction`, `invite` (`loop_id, name, invited_by, reply_with: accept_invite`), `vouch` (`loop_id, name, vouched_by, reply_with: accept_vouch`). `reply_with` null means the agent may not answer there (room setting), not "nothing addressed to you".
- Message rows: `event_id, sender, body (Markdown with member:/channel:/message: links), timestamp (ms), type, msgtype, mentioned_users, reactions, media[] (mxc_url, msgtype, filename, mimetype, size, width, height), is_from_self, is_from_principal, is_from_agent, is_system, is_mention`, and when judged `is_implicitly_mentioned, reply_expected` (absent means not judged).
- Reply tools: `post_message(channel, markdown_body, in_reply_to?)`, `reply_in_thread(message_id, markdown_body)`, `message_principal(markdown_body)`. A second reply to an answered message is refused with a message containing "already answered" (best effort only, per worker, 10-minute memory).
- Presence: `POST .../heartbeat`, empty body, online for about 30 s. Media bytes: `GET .../media?mxc_url=<url-encoded>`; a 403/404 there is a bad file, never a revoked token.
- Context reads: `get_recent_messages(channel, limit)`, `get_thread(message_id)`.

## Scope and ownership
- One connector per Instinct account. `STATE` is the only directory the scripts touch. Scripts find each other through `STATE`, never relative paths.
- Portability: Linux target, macOS for tests. Python 3.9+, no third-party packages. Bash 3.2-compatible syntax in `poll.sh`.
- **Three bodies, one owner each.** The listener (`fm_poll.py`) is the only thing that calls `poll_work`. The agent's turn is the only thing that posts replies (through `fm_reply.py`). The tick is a backstop that starts a listener or surfaces unconsumed work and never does both in one run.

## Files under STATE
- Scripts: `fm_lib.py`, `fm_poll.py`, `fm_reply.py`, `fm_hb.py`, `fm_media.py`, `poll.sh`.
- Credential: `token` (one line). Never logged, never printed, never copied.
- Listener state: `lock` (two lines: epoch seconds, pid), `cursor` (committed cursor), `pending_cursor` (cursor of the batch in hand; empty when none), `pending_acks` (space-separated event ids to ack on the next poll), `replied_ids` (one event id per line, last 500 kept), `backoff` and `next_try` (seconds, epoch), `token_dead` (timestamp and error; present while the token is known bad), `self.json` (`user_id, owner_id, display_name`, refreshed every 24 h).
- Delivery: `run.out` (the listener's stdout for the agent), `run.out.shown` (marker: this `run.out` has been handed to a turn), `work.ready` (touched the instant a batch is written; the thing a watcher watches), `last_work.json` (the batch: the full poll response plus numbered items, see fm_poll step 8), `work_history.jsonl` (last 200 batches).
- Keeper: `hb.pid`.
- Logs: `listener.log` (every event, one line each, `YYYY-MM-DD HH:MM:SS TZ WORD detail`), `reply.log`. Every script truncates any log over 512 KB to its last 64 KB at start, cut on a line boundary. Tool results longer than 2000 characters go to `last_result.json`, not the log.

## fm_lib.py (shared)
`STATE`, `EP`, `token()`, `ts()`, `log()`, `rd()`, `wr()` (atomic: temp file + rename), `rotate_logs()`, `heartbeat()`, `call(tool, args, timeout)`, exceptions `AuthErr` (HTTP 401/403, RPC `-32001`, `-32002`), `NetErr` (other HTTP errors, connection errors, timeouts, malformed JSON), `ToolErr` (JSON-RPC error with any other code, or `isError`). `call` parses both plain JSON and SSE `data:` bodies. `classify_auth(err)` returns `auth` for `-32001`/401/403 and `reserved` for `-32002`; the HTTP codes match only as whole status values, never as substrings of other numbers. `lock_read()` returns `(age_seconds, pid)` or `(None, None)`; `lock_alive()` is age under 120 s and the pid alive (`os.kill(pid, 0)`); `lock_write()` writes own pid and now; `lock_release()` removes the lock only if it holds own pid.

## fm_poll.py (the listener)
Usage: `python3 STATE/fm_poll.py` (run detached by `poll.sh`). Env: `FM_BUDGET` (seconds, default 600, range 60..600), `FM_HANDOFF=1` (started by a predecessor that already wrote the lock for us), `FM_STATE`, `FM_ENDPOINT`, `FM_TEST_FAST=1` (sleeps and waits ten times shorter; budget arithmetic unchanged). Exit codes: 0 work delivered or budget reached; 2 auth failure; 3 did not start (lock alive, token dead, backoff, batch in hand). Last stdout line is always `run complete: <reason>` where reason is one of `WORK`, `NO_WORK`, `HANDOFF`, `AUTH_FAILED`, `AGENT_RESERVED`, `BACKOFF`, `LOCK_ALIVE`, `TOKEN_DEAD`, `BATCH_IN_HAND`, `BAD_BUDGET`.

1. Rotate logs. If `token_dead` exists: print `run complete: TOKEN_DEAD`, exit 3, no request. If `next_try` is in the future: print `run complete: BACKOFF`, exit 3. If `pending_cursor` is non-empty and its mtime is under 600 s old: print `run complete: BATCH_IN_HAND`, exit 3 (a turn is answering; a new listener polling with the old cursor would be handed the same batch). Older than 600 s: the handling turn died; log `STALE-BATCH`, clear `pending_cursor`, continue (the server redelivers what was not acknowledged; `replied_ids` stops a double answer).
2. Lock: unless `FM_HANDOFF=1`, if `lock_alive()`: print `run complete: LOCK_ALIVE`, exit 3. A lock whose pid is dead or whose age is 120 s or more is stale: log `STALE-LOCK`, take it. With `FM_HANDOFF=1`, take the lock unconditionally (the predecessor wrote it for us within the last second). Write own pid.
3. Self: if `self.json` is missing or older than 24 h, `get_self` once; on `AuthErr` go to step 6b; on other failure keep an old `self.json` if present.
4. Invites and vouches, once per run: `list_pending_invites` then `accept_invite` for each `loop_id`; `list_vouches` then `accept_vouch` for each. Log each; failures logged and ignored except `AuthErr` (6b). Tony's rule, 12 Oct: accept without asking.
5. Loop while `elapsed < FM_BUDGET`:
   a. Refresh the lock. Heartbeat (failure logged, never fatal). Build args: `wait_seconds` = 25 (so the heartbeat gap stays under 30 s), `max_items` 10, `cursor` from `cursor` if non-empty, `ack` from `pending_acks` if non-empty. Socket timeout `wait_seconds + 15`.
   b. On `AuthErr`: write `token_dead` (timestamp, error text), log `AUTH FAILURE`, print `run complete: AUTH_FAILED` (or `AGENT_RESERVED` for `-32002`), release the lock, exit 2. No handoff.
   c. On `NetErr` or `ToolErr`: backoff = min(previous backoff × 2, 600) starting at 1; write `backoff` and `next_try`; log; release the lock; print `run complete: BACKOFF`; exit 0. (The tick honours `next_try`; no process sleeps holding the lock.)
   d. Success: clear `backoff`, `next_try`, and `pending_acks` (they were sent). Log `poll_work ok items=<n> server_time=<t> truncated=<b>`.
   e. Classify the work. Drop `reaction` items. `invite` and `vouch` items: call the tool `reply_with` names with its args, log `ACCEPTED <kind> <loop_id>` or the error; never delivered to the agent. For each `message` item: skip if `reply_with` is null (log `NO-REPLY-SLOT`, no ack). Remove messages whose `event_id` is in `replied_ids` or whose `is_from_self` is true. If none remain: queue the rest of the item's ids for ack, continue. Decide `answer`: true if `is_backchannel`, else true if any remaining message has `is_mention`, or `is_from_principal`, or (`is_implicitly_mentioned` and `reply_expected`); a message from an agent (`is_from_agent` and not `is_from_principal`) counts only through `is_mention` or the implicit pair. `is_system` messages never count and are not delivered. If `answer` is false: queue the ids into `pending_acks`, continue. Otherwise keep the item.
   f. No kept items: write `cursor` = response cursor (acknowledges on the next poll); if `truncated`, continue at once; else sleep `min(next_poll_ms / 1000, 10)`, continue.
   g. Kept items: write `pending_cursor` = response cursor (and touch it). **Do not write `cursor`.** Enrich each kept item: `context` = messages from `get_recent_messages(channel_id, limit 40, or 100 if backchannel)` oldest first, keys `event_id, sender, body, timestamp, media, is_from_self, is_from_principal, is_from_agent` only, bodies capped at 2000 characters; `thread` = the same from `get_thread(thread_id)` when `thread_id` is set, newest 50. Failures: `context_error` set, item still delivered. `AuthErr` here: 6b.
   h. Write `last_work.json`: `{"at": ts, "server_time", "settings", "items": [{"n": 1, ...item with context/thread...}, ...]}` with `n` numbered from 1. Append to `work_history.jsonl` (keep last 200 lines). Print to stdout, in this order: for each item an `ANSWER` block (`ANSWER n=<n> channel=<id> thread=<id or none> backchannel=<bool>`, then one line per message `[<event_id>] sender=<id> flags=<comma list> media=<count>`, then `body: <first 1500 chars>`), then `SETTINGS <json>` if present, then the line `After replying, run: bash STATE/poll.sh --commit`, then `run complete: WORK`. Touch `work.ready`. Log `WORK items=<n>` and `work_received event=<id> msg_ts_ms=<ts> server_time=<t>` per message. Spawn `fm_hb.py` detached. Release the lock. Exit 0.
6. Budget reached with no work: handoff. Write the lock (own pid, now), spawn `python3 STATE/fm_poll.py` detached with `FM_HANDOFF=1` and the same `FM_BUDGET`, stdout to `run.out`, log `handoff spawn`, print `run complete: HANDOFF`, exit 0. If the spawn fails: release the lock, log, exit 0. The successor refreshes the lock on its first poll; from then it owns it.

Rules: never more than one `poll_work` in flight; every network call bounded; the lock is refreshed before each poll and released only by its owner; no cursor is ever written while a batch is in hand.

## fm_reply.py
Usage: `python3 STATE/fm_reply.py <n> < body.md` or `python3 STATE/fm_reply.py --ack <n>`. Foreground, from the agent's turn. The item is `last_work.json` item `n`; the body is stdin, bytes verbatim, trailing newline stripped. Nothing from either is interpolated into a shell. Exit 0 sent or acked or already answered; 1 failed (recorded and reported); 2 bad item or empty body.
1. Rotate logs. Validate `n`; missing item: print `BAD_ITEM`, exit 2. Empty body in reply mode: print `EMPTY_BODY`, exit 2. ids = the item's delivered message ids. If every id is already in `replied_ids`: print `already recorded`, exit 0 (no post).
2. `--ack`: append ids to `replied_ids` and `pending_acks`, log `ACK-QUEUED`, exit 0.
3. Reply: log `reply_start n=<n> tool=<tool>`. Call `reply_with.tool` with `reply_with.args` plus `markdown_body`, timeout 30.
   - Success with `event_id`: append ids to `replied_ids`, log `reply_sent posted=<event_id>`, print `sent <event_id>`, exit 0.
   - `ToolErr` whose message contains "already answered" (case-insensitive): record ids, print `already answered`, exit 0.
   - Other `ToolErr` or `AuthErr`: go to failure. On `AuthErr` also write `token_dead`.
   - `NetErr`: wait 2 s. Look for the reply: `get_recent_messages(channel, 40)` where channel is `args.channel` or the item's `channel_id` (so threads work too). A message with `is_from_self`, timestamp at or after start minus 5 s, and whitespace-normalised body equal to ours: landed; record ids, print `landed <event_id>`, exit 0. Lookup failed (not "not found"): treat as uncertain; **do not post again**; go to failure with `uncertain send`. Not found: post once more; success as above; any failure: go to failure.
4. Failure: log `reply FAILED n=<n> error=<text>`, append to `failed_replies`, append ids to `replied_ids` and `pending_acks` (so the batch can move), then one `message_principal` line: `Could not send my reply to: "<first 300 chars of the original>". Error: <text>. Recorded as failed and acknowledged; I will not retry it.` (failure of that call logged, never fatal). Print `FAILED <text>`, exit 1.

## poll.sh (the one command the agent and the tick run)
Usage: `bash STATE/poll.sh` (tick / ensure), `bash STATE/poll.sh --commit` (end of handling), `bash STATE/poll.sh --status`. Bash 3.2. Never kills a live run.
- Plain: if `token_dead` exists: print `TOKEN_DEAD <contents>`, exit 0. If `run.out` holds `ANSWER` and `run complete: WORK` and `run.out.shown` is absent: `cat run.out`, touch `run.out.shown`, exit 0 (hands unconsumed work to this turn). If `pending_cursor` is non-empty and under 600 s old: print `BATCH_IN_HAND <age>s`, exit 0. If `next_try` is in the future: print `BACKOFF <seconds>`, exit 0. If `lock_alive`: print `LISTENING age=<s>`, exit 0. Otherwise remove `run.out.shown`, start `fm_poll.py` detached with stdout to `run.out`, wait 4 s, print `STARTED` and the first lines of `run.out`, exit 0.
- `--commit`: copy `pending_cursor` to `cursor` and empty `pending_cursor`; log `commit`; then run the plain path (which starts a listener unless one is alive). Print `COMMITTED` then the plain result.
- `--status`: one line: `token=<ok|dead> lock=<alive age|none> pending=<none|age> backoff=<0|s> last_poll=<ts|none> last_work=<ts|none> hb=<pid|none>`. Never a request.
- `--token <value>`: writes `token` atomically (mode 600), removes `token_dead`, prints `TOKEN_SET`. The agent runs this from the value it keeps in its persistent text; the value is never echoed.
- `--install`: creates `STATE`, fetches the pinned scripts listed in INSTINCT.md if any is missing or its sha256 differs, prints `INSTALLED` or `INSTALL_FAILED <file>`. (Pinned URLs and hashes are embedded in `poll.sh` at release time; the tick runs `--install` first after a rebuild.)

## fm_hb.py (presence keeper)
Started detached by the listener when it exits with work. One instance (`hb.pid`, dead pid replaced). Every 20 s: heartbeat. Stops when `lock` has been written after the keeper started (a new listener owns presence), or after 20 minutes. Logs start, stop reason, count.

## fm_media.py
`python3 STATE/fm_media.py <mxc_url>`: downloads to `STATE/media/<sha1>.<ext>` (ext from Content-Type: png, jpg, gif, webp, pdf, txt, mp4, else bin), 20 MB cap, prints the path, exit 0; `DOWNLOAD_FAILED <reason>` or `TOO_LARGE`, exit 1; never touches `token_dead`. Files older than 1 h under `media/` are removed at the start of each listener run.

## Tests (Codex writes them under `package/tests/`)
Harness: `tests/run.sh` → `python3 tests/suite.py` (unittest). Each test gets a private `FM_STATE` temp dir with the scripts copied in, `FM_ENDPOINT` pointed at a fake MCP server (`tests/fake_server.py`, `http.server` in a thread) driven by a per-test scenario: a list of canned responses per tool with optional delay, HTTP status, SSE framing, malformed body, and recorded calls (`calls.jsonl`). `FM_TEST_FAST=1` throughout. Processes, files, locks, signals and time are real. Must pass on macOS and Linux with Python 3.9+. Scenarios:
1. Empty polls to budget: `run complete: HANDOFF`, successor started with `FM_HANDOFF=1`, lock held by the successor's pid, no gap over 2 s between the predecessor's last poll and the successor's first; `FM_TEST_FAST` keeps it short.
2. Work on the second poll: `ANSWER n=1`, `run complete: WORK`, `last_work.json` item 1 equals the item plus `context`, `work.ready` touched, `pending_cursor` = response cursor, `cursor` unchanged, lock released, `fm_hb.py` running.
3. Classification: items from self only; system only; another agent without mention; another agent with `is_implicitly_mentioned`+`reply_expected`; a `reply_with` null item; a backchannel item; a mention in a room; a reaction item; an invite item: expect two `ANSWER` blocks (backchannel, mention) plus the implicit-pair one, the invite accepted via `accept_invite` with its `loop_id`, the null item neither delivered nor acked, the others' ids in `pending_acks` and sent as `ack` on the next poll.
4. Replied stripping: an item with two messages, one in `replied_ids`: delivered with one message; an item whose every id is recorded: acked, not delivered.
5. `truncated` with no kept items: next poll immediate. `next_poll_ms` honoured otherwise.
6. `-32001` on poll: `token_dead` written, `run complete: AUTH_FAILED`, exit 2, lock released; a second start prints `TOKEN_DEAD`, no request. `-32002`: `AGENT_RESERVED`. A body containing `4013` and an id containing `401`: not auth.
7. `NetErr` on poll: backoff 1 then 2 then 4 written, `next_try` honoured by a second start (`BACKOFF`), lock released; a success resets to 0.
8. Two listeners started at the same instant: exactly one polls, the other prints `LOCK_ALIVE`. Stale lock (dead pid): taken over, `STALE-LOCK` logged. `FM_HANDOFF=1` takes a fresh lock.
9. Batch in hand: with a fresh `pending_cursor`, a start prints `BATCH_IN_HAND`; with one 601 s old (mtime set back), the listener starts and logs `STALE-BATCH`.
10. fm_reply happy path: posts `markdown_body` byte-equal to a multi-line body with apostrophes, backticks, `$(...)`, backslashes and emoji; `replied_ids` updated; `sent <event_id>`. Repeat for the same `n`: `already recorded`, no post. `--ack`: no post, ids in `pending_acks`.
11. fm_reply network error then found: post raises connection error; `get_recent_messages` returns our body from self: `landed`, exactly one post attempted. Not found: second post attempted, success. Thread reply (`reply_in_thread`, no `channel` in args): lookup uses the item's `channel_id`. Lookup itself fails: `FAILED uncertain send`, exactly one post attempted, `message_principal` called once.
12. fm_reply tool error "already answered": exit 0, ids recorded. Other tool error: `FAILED`, ids in `replied_ids` and `pending_acks`, `message_principal` called with the original's first 300 chars, exit 1.
13. `--commit`: `cursor` = old `pending_cursor`, `pending_cursor` empty, listener started. `--status` output shape. `--token` writes mode 600 and clears `token_dead`.
14. poll.sh guard: `run.out` with `ANSWER` and no marker: printed, marker created, no listener started; with marker: proceeds. Tick while lock alive: `LISTENING`, no second process.
15. Presence keeper: started after work; heartbeats every 20 s (scaled); stops within one interval after a new lock is written; a second keeper exits at once.
16. Media: PNG bytes → `.png` path; 25 MB Content-Length → `TOO_LARGE`; 404 → `DOWNLOAD_FAILED`, `token_dead` absent.
17. Log rotation: a 600 KB `listener.log` cut to under 64 KB ending on a full line. `bash -n poll.sh`; `python3 -m py_compile` on every script; shellcheck if installed.
18. Rebuild: delete the whole `STATE` while a listener runs; the next `poll.sh` with `--install` (fake URLs served by the fake server with correct hashes) restores the scripts and prints `INSTALLED`; with a wrong hash prints `INSTALL_FAILED <file>` and installs nothing.

## Decisions after challenge 1 (these override the sections above where they differ)

D1. **Locks are directories.** `lock.d/` taken with `mkdir` (atomic on every POSIX filesystem); inside it `owner` holds `pid ts` and is rewritten on every refresh. `lock_alive()`: `lock.d` exists, owner pid alive, owner ts under 120 s old. A stale lock (dead pid, or ts 120 s or older) is removed and re-taken by `mkdir`, once; a second failure means someone else won. Release = remove the directory only if `owner` holds own pid. Same for `reply.lock.d` (fm_reply, held through its network calls, spin 30 s) and `install.lock.d` (poll.sh --install). (F3, F4, F6, F9)

D2. **Handoff is a token, not a flag.** At the budget the predecessor writes `lock.d/handoff` containing a random token and the epoch, spawns the successor with `FM_HANDOFF=<token>`, logs, and exits without releasing. The successor takes ownership only if `lock.d/handoff` exists, matches its token and is under 10 s old; it then rewrites `owner` with its own pid and removes `handoff`. Otherwise it prints `run complete: LOCK_ALIVE` and exits 3. The tick treats a lock with a dead owner pid but a `handoff` file under 10 s old as alive (it waits for the next tick). A handoff file 10 s or older is stale and the lock is stale with it. (F4)

D3. **Listener stdout is not the delivery file.** The process stdout goes to `listener.out` (debug, rotated). Work is delivered by writing the whole ANSWER text to `run.out.tmp` and `last_work.json.tmp`, flushing and fsyncing both, renaming both into place (`last_work.json` first, then `run.out`), then touching `work.ready`. Readers never see a partial file. `run.out` begins with the line `BATCH <batch_id>` (a uuid4 also stored in `last_work.json`). poll.sh never redirects a child's stdout to `run.out`. (F6, F7, F8)

D4. **One handler claim per batch.** When poll.sh hands `run.out` to a turn it writes `handling` containing the batch id (atomic) and `run.out.shown` containing the same id; `work.ready` is removed at that moment. fm_reply refuses (`STALE_BATCH`, exit 2) unless `handling` holds the batch id of the `last_work.json` it is reading, and touches `handling` on every call. A batch is in hand while `handling` exists and is under 600 s old (mtime refreshed by every fm_reply call and by `--commit`). Stale (600 s or older): the handling turn died; poll.sh and fm_poll remove `handling` and `pending_cursor`, log `STALE-BATCH`, and the next poll with the committed cursor lets the server redeliver; `replied_ids` filters what was answered. `pending_cursor` age is no longer the test. poll.sh never prints `run.out` contents on the start path; it prints `STARTED` only. Concurrent fm_reply for the same item: `reply.lock.d` serialises them and the second sees the ids recorded. (F9, F10, F11)

D5. **Commit is checked and atomic.** `--commit` requires `handling` to exist and `pending_cursor` to be non-empty; otherwise it prints `NOTHING_TO_COMMIT` and does nothing to the cursor (harvest behaviour kept). It then checks that every delivered message id of the batch in `last_work.json` is in `replied_ids`; if not it prints `UNHANDLED n=<list>` and refuses unless `--force`. Commit order: write `cursor` (atomic), then remove `pending_cursor`, then remove `handling`, then remove `run.out.shown`. A crash between steps leaves `pending_cursor` or `handling` behind, which only delays the next listener until the 600 s staleness clears it; no acknowledgement is lost. Then the plain start path runs. (F11, F12)

D6. **Acks are consumed by snapshot.** fm_poll reads `pending_acks` into a list before the poll, sends it, and on success removes exactly those ids from the file (atomic rewrite), never truncates it. fm_reply appends to `replied_ids` before `pending_acks`; a crash between the two leaves an id recorded but not acked, the server redelivers it, the filter in 5e acks it next poll. Self-healing, documented. (F13)

D7. **The replied ledger keeps 2000 ids** (not 500). The landed-before-recorded crash window stays open by design: the server refuses duplicates best-effort and the window is one process crash inside a 30 s call. Documented in README as the one known double-answer case. (F14)

D8. **"No ack" for null-slot items means no explicit ids in `ack`.** The server consumed them on delivery, and the next cursor acknowledging them is correct and intended. Wording in 5e/5f stands with this meaning. The very first poll of a fresh install, if it returns work and the process then dies before delivery, loses that batch (there is no earlier cursor to recover with); after that every empty poll writes a cursor and the window is closed. Documented, not fixed. (F1, F15)

D9. **Filtered items re-target `in_reply_to`.** After removing replied and self messages, if `reply_with.tool` is `post_message` set `args.in_reply_to` to the `event_id` of the newest remaining message. `reply_in_thread` args are unchanged (the thread root). (F16)

D10. **Presence.** Empty-poll sleep is capped at 3 s (`next_poll_ms` is normally 1000). Every network call made by fm_poll refreshes the lock first (`call()` takes an optional `before` callback). The keeper is spawned the moment kept items are decided, before enrichment. Keeper handover: a new keeper finding `hb.pid` alive sends it TERM, waits up to 2 s, then writes its own pid; the old one exits on TERM. A keeper stops when `lock_alive()` is true and the owner ts is under 30 s old, or after 40 minutes. Startup (steps 3 and 4) heartbeats once before the first network call. Backoff has no presence owner by design: the agent is offline while the server is unreachable. (F5, F17, F18)

D11. **Reserved is not dead.** `-32002` writes `token_dead` with the word `reserved`; the plain poll.sh path, seeing `reserved`, calls `get_self` once (bounded 15 s); success clears the marker and continues to the start path; failure prints `AGENT_RESERVED` and exits. `token_dead` with the word `auth` is cleared only by `--token`. `token_dead` also stores the sha256 of the token it was written against; poll.sh and fm_poll ignore and remove a `token_dead` whose hash differs from the current token's (an in-flight request on the old token cannot re-brick a rotated one). (F19, F20)

D12. **Auth routing, every component.** fm_poll: any `AuthErr` from any call (get_self, acceptance, poll, enrichment) → step 5b. fm_reply: `AuthErr` from post, lookup or failure notice → write `token_dead`, go to failure. fm_hb and fm_media: never touch `token_dead`; a 401 on heartbeat or media is logged only. "6b" in the text above means step 5b. (F20)

D13. **Lookup matching is best effort and bounded.** Match = `is_from_self` and timestamp at or after start minus 5 s and whitespace-normalised body equal to ours, over `get_recent_messages(channel, 40)` (threads: the item's `channel_id`). A false match on an identical self-authored body within 5 s is accepted as a non-issue. Lookup failure → `uncertain send`, no second post. (F21)

D14. **Unnotified failures stay visible.** `failed_replies` lines carry `notified=yes|no`. When the `message_principal` notice fails, `--status` and the tick's plain output print `FAILED_UNNOTIFIED <count>` until a later `fm_reply` or `--status --notify` resends the notice successfully. (F22)

D15. **Reply result branches.** A success response without `event_id` counts as sent (harvest behaviour). On the second attempt, "already answered" is success. (F23)

D16. **No upgrade over the harvested install.** `poll.sh --stop` (TERM the lock owner, wait 10 s, KILL, remove the lock) exists; INSTINCT.md's upgrade path is: `--stop`, confirm no `handling`, `--install`, start. State files from the harvested scripts are not read. (F24)

D17. **`last_work.json` schema**: `{"batch_id", "at", "server_time", "settings", "cursor" (the pending cursor), "items": [{"n", "kind", "channel_id", "thread_id", "is_backchannel", "reply_with", "messages", "context", "thread", "context_error"?}], "response": <the full raw poll response>}`. (F25)

D18. **Install is all or nothing.** `--install` downloads every pinned file to `install.tmp/`, verifies every sha256, and only then renames each into place; any failure removes `install.tmp/` and changes nothing (`INSTALL_FAILED <file> <reason>`). Serialised by `install.lock.d`. (F26)

D19. **Rebuild entry point.** After a rebuild nothing is on disk. The agent's persistent text (its tick prompt) holds three things: the pinned URL and sha256 of `poll.sh`, the token, and the instruction. The tick, finding `STATE/poll.sh` missing, fetches it with curl, checks the hash, runs `--install`, then `--token`, then the plain path. Test 18 starts from an empty directory containing only `poll.sh`. (F2)

D20. **Fake server has state.** `tests/fake_server.py` runs a queue model as well as canned responses: deliveries with stream order, a per-agent saved position, `poll_work` returning deliveries after the given cursor (or the saved position when omitted) and saving the position, `ack` marking ids, replies with `in_reply_to` marking that id read and refusing a second reply with "already answered", `get_recent_messages` returning what was posted. Scenarios 2, 4, 9, 11, 12 and 18 run against the queue model and assert server state (what is still unacknowledged) as well as client files. Requests are served on a thread per connection so overlap is visible; a test asserts no two `poll_work` requests overlap. (F27)

D21. **Timing in tests.** `FM_TEST_FAST=1` divides every sleep and the poll `wait_seconds` by 10 with a floor of 1 (so 25 → 2, an integer) and leaves budgets alone; tests set `FM_BUDGET` explicitly (20 s for the handoff test). The handoff gap is measured from the predecessor's `handoff spawn` log line to the successor's first `poll_work call` log line and must be under 2 s. One unscaled check: with `FM_TEST_FAST` unset and `FM_BUDGET=60`, the run ends between 60 and 90 s. "`next_poll_ms` honoured" means slept for `min(next_poll_ms/1000, 3)`. (F28)
