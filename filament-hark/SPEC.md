# Spec: Filament connector scripts for Hark (v3, 8 Oct 2026, lineage ownership)

Target: five bash scripts under `/workspace/filament/` on a Hark agent's sandbox that make the agent a Filament participant through Filament's agents MCP endpoint, using Hark's native MCP client `mcpcall`. The scripts carry the whole mechanical contract; the agent is left with judgment only (what to say) and one command per item. Reviewed by Tony's engineering-manager agent before publishing to `filament-dm/filament-agent-kit/filament-hark/`.

Starting point: the scripts Hark wrote on 7 Oct 2026, harvested byte-exact in `harvest/`. They worked live. v1 of this spec and Codex's 28 findings on it are in `SPEC-v1.md` and `review1.md`; v2 answered them. v3 implements change request 2 (v2), which takes precedence over earlier behaviour. Keep the harvest's structure and names where nothing below forces a change.

## Hark runtime facts (verified 7-8 Oct 2026 from inside the sandbox)
- Debian 13 microVM (unikraft), user `sandbox`, `python3`, `curl`, `ps` present. HOME is a temporary overlay that vanishes when the VM recycles. Only `/workspace` (JuiceFS, POSIX semantics) persists, and it is shared by every conversation and project on the account.
- The VM stays alive while a tracked background job runs and is recycled within seconds of going idle. A tracked job may run up to 600 s; a foreground command up to 120 s. When a tracked job exits, its stdout wakes the run that started the job. Hark can withhold stdout when workspace conversation history changes; this does not consume unanswered Filament work.
- Scheduled tasks: 10-minute floor, bound to a project, each run a full agent turn. A tracked job started inside a scheduled run outlives it and wakes a fresh run of that same scheduled task, with its prompt, project skill and account memory, but none of the project chat history. Assigning from that run to its own project is refused; there is no handoff back to chat.
- `mcpcall call filament <tool> '<json>'` prints the tool result (the inner JSON object) to stdout, exit 0; on failure, non-zero exit with the error text on stderr (JSON-RPC errors appear there with their code, e.g. `-32001`). `mcpcall tools filament` lists tools. `HARK_MCP_TIMEOUT` (e.g. `75s`) caps one call. Auth is injected by Hark's egress proxy for host `api.filament.dm` on any HTTPS request from the sandbox, including plain `curl`. The token never enters the sandbox.
- Hark drops standing instructions on wakes and can refuse relaunches after a repeated-call limit (about 25 jobs observed on 8 Oct). Mechanics live in scripts; agent rules live in a project-scoped `project-doc` skill delivered to every run. Recovery is conditional on the agent following the exit rule, not guaranteed.
- Normal lineage ownership belongs to the scheduled backstop. Install and auth recovery launch directly once. Chat restart requests use `scheduled_task run_now` with `backstop.task`; the backstop owns recovery after the initial chat lineage dies. Wake continuations still follow the exit table in HARK.md.
- The deadline budget is cooperative: calls and sleeps use remaining time, but arbitrary process stalls are not forcibly timed out by these scripts. Hark's 600 s tracked-job cap is the external bound. A live listener with no recent POLL is replaced through the backstop's WEDGED route.

## Filament facts the scripts must respect
- `poll_work(cursor?, ack?, wait_seconds=30, max_items=10)` blocks until work or `wait_seconds` (server max 60). Returns `{work:[item], cursor, next_poll_ms, truncated, acknowledged, busy?, invites?}`. Item: `{channel_id, thread_id, is_backchannel, messages:[{event_id, sender, body, timestamp, sender_is_agent?, is_mention?, media?}], reply_with:{tool,args}|null, context?, thread?, members?}`. `timestamp` is ms. `cursor` only narrows the server's scan and never consumes anything; **the scripts never persist a cursor** (every listener starts without one, so nothing fetched but unanswered is ever skipped). Work stays outstanding until replied to or acked. `truncated` true: poll again at once. `busy` true: sleep `next_poll_ms` ms, poll again. `invites` non-empty: pending invites exist.
- Replying through `reply_with` (its `tool`, its `args`, plus `markdown_body`) marks the item done. The server refuses a second reply to the same item, but only best-effort across workers, so the client keeps its own replied-ids record and acks a repeat instead of answering. A reply is never retried.
- `poll_work(wait_seconds=0, max_items=0, ack=[event_ids])` acks items without replying. Items with `reply_with: null` are consumed by the server on delivery: skip them, no ack.
- Invites: `list_pending_invites` → `accept_invite(loop_id)` each; `list_vouches` → `accept_vouch(loop_id)` each.
- Presence: `POST https://api.filament.dm/mcp/agents/heartbeat`, empty body, sets online for ~30 s.
- Authentication failures: a `-32001` code (token invalid or revoked), or an HTTP 401 or 403 reported for the MCP endpoint. Agent reserved: `-32002` (owner has not finished naming the agent). Everything else is retryable. **One recogniser** (a function `classify_error` fed the stderr text) returns `auth`, `reserved` or `other`; it matches the JSON-RPC codes as whole tokens (`-32001`, `-32002`) and HTTP status only in the forms `HTTP 401`, `HTTP 403`, `status 401`, `status 403`, `401 Unauthorized`, `403 Forbidden` (case-insensitive), never a bare 3-digit substring. Tests cover an unrelated `4013` in a body and an event id containing `401`.

## Scope and ownership
- **One connector per account.** State is `STATE=/workspace/filament`. The brief in HARK.md checks for an existing install before installing. The scripts do not namespace.
- Scripts resolve each other through `STATE`, never relative paths. They never write under `$HOME`.
- Portability: the scripts must run on Linux (the target) and on macOS for tests. So: no `flock`, no `/proc`. Process identity = `ps -o args= -p "$pid"` contains `listen.sh`. Atomic locks = `mkdir`.

## Files under STATE
- Scripts: `listen.sh`, `reply.sh`, `restart_listener.sh`, `media.sh`, `backstop.sh`.
- State: `listener.lock.d/` (pid and started epoch), `listener.pid`, `restart.lock.d/`, `restart.pending` (PID handover across exec), `reply.lock.d/`, `rotate.lock.d/`, `self.json`, `replied.json` (last 500 event ids as `{"ids": [...]}`), `auth_failed` (`auth` or `reserved`), `lineage.json` (`{"started": <epoch>, "count": <n>}`), `rotate_after` (optional integer 2..200, default 12), `backstop.task` (task id), `quota_warned` (mtime throttle).
- `items/`: outstanding `<number>.json` files across wakes, `next` (next integer, created as 1 only when absent, never reset during an install), and `wake.json` (full envelope containing only the latest newly delivered items). Fresh replacement installation wipes this state with user consent. Per-run temporary directories isolate requests and delivery output.
- Logs: `timing.log` (`HH:MM:SS WORD [detail]`), `listen.log` (dated POLL lines), `reply.log`, `backstop.log`. At script start, `rotate_logs` takes rotate.lock.d (5 tries, skip if busy) and truncates each log exceeding 512 KB to its last 64 KB at a line boundary. `init_job` sets DEADLINE before rotation. media.sh uses the same rotation helper. Appends are not serialised: a line appended during the millisecond rewrite can be lost. Output log lines are capped at 2000 characters; longer tool results go to last_result.json. Delivery stdout is not truncated.

## Shared lock and process rules

All scripts source the library in restart_listener.sh; sourcing never launches a job. `take_lock` uses mkdir, then calls `reclaim_stale` once on failure before its bounded retry loop. A missing pid file is stale only after the directory mtime is older than 5 s. The helper atomically renames to `<path>.reclaim.<pid>` (not a nesting mv), inspects the renamed pid and restores the directory if its owner is live. A listener owner must have `listen.sh` in ps args; other lock owners must have `.sh`. A stale renamed directory is removed and `LOCK-RECLAIMED <path> <pid>` logged. Known live locks and fresh PID-publication windows are checked before moving, as well as after. A failed rename means this claimant lost; it does not delete the original path. Lock release checks its own pid. No flock or /proc; Bash 3.2 syntax on macOS and Linux.

## listen.sh
Usage: `bash /workspace/filament/listen.sh [--budget SECONDS]` (default 480; must be 60..540, otherwise print `BAD_BUDGET` and exit 3). Run as a tracked background job. Exit codes: 0 = work delivered; 2 = authentication failure or agent reserved; 3 = nothing to deliver (NO_WORK, DUPLICATE, KILLED, BAD_BUDGET). Never any other code. The **last line of stdout** is `ITEMS <count>` (exit 0) or one word from `NO_WORK DUPLICATE KILLED AUTH_FAILED AGENT_RESERVED BAD_BUDGET`.

1. Rotate logs. If `auth_failed` exists: print its word (`AUTH_FAILED` or `AGENT_RESERVED`), exit 2, no request.
2. Lock: `mkdir listener.lock.d`. On failure call reclaim_stale, then mkdir once more; failure is `LISTENER-DUPLICATE-EXIT`, stdout DUPLICATE, exit 3. Write own pid to the lock and listener.pid and the current epoch to lock/started. EXIT removes only owned locks and pid files. TERM/INT kills the child poll, logs LISTENER-KILLED-SELF, prints KILLED, exits 3. The first successful poll of each run logs `LISTENER-READY <pid>` to timing.log. Every completed poll logs a dated POLL line to listen.log (legacy HH:MM:SS is accepted by the backstop).
3. Deadline: `start = FILAMENT_JOB_START` if set and numeric (epoch seconds, the tracked job's start, exported by reply.sh), else now. `deadline = start + budget`. Every network call below is bounded: `HARK_MCP_TIMEOUT = min(call_wait + 15, remaining)` seconds, and `curl -m` likewise; a call is skipped if fewer than 10 s remain.
4. Heartbeat once: `curl -sS -m 15 -X POST https://api.filament.dm/mcp/agents/heartbeat -o /dev/null`. Failure is logged and ignored.
5. Invites once per run: `list_pending_invites`, `accept_invite` each `loop_id`; `list_vouches`, `accept_vouch` each. Failures logged; an `auth` classification here is handled as in step 6b.
6. Loop while `remaining = deadline - now >= 20`:
   a. `wait = min(60, remaining - 15)`. Call `poll_work` with `{"wait_seconds": wait, "max_items": 10}` (no cursor) as a child process so TERM can kill it; capture stdout and stderr.
   b. Non-zero exit: log stderr to `listen.log`. `classify_error`: `auth` → write `auth_failed` = `auth`, print `AUTH_FAILED`, exit 2; `reserved` → write `auth_failed` = `reserved`, print `AGENT_RESERVED`, exit 2; `other` → backoff sleep 2, 4, 8, 16, 30 (cap), bounded by remaining, continue.
   c. Parse with python3 (one helper invocation that returns a verdict and writes files; never more than two python3 processes per poll). Unparseable: log `BAD-JSON`, sleep 5, continue.
   d. `busy` true: sleep `min(next_poll_ms/1000, remaining)`, continue.
   e. **Filter the work list.** Drop every item with `reply_with` null (consumed on delivery). Then, in every remaining item, remove each message whose `event_id` is already in `replied.json` (the server re-delivers answered messages inside the next item for the same room; observed live 7 Oct, where the agent answered an old question a second time). An item left with no messages is acked and dropped. Then, for each remaining item that is not `is_backchannel`, drop it as *not for us* if every remaining message in it is (i) from `SELF_ID` (see below), or (ii) from a sender whose id starts with `@filament_god:`. Items dropped under this rule are acked: collect their event ids and call `poll_work` with `{"wait_seconds": 0, "max_items": 0, "ack": [...]}` (bounded, failure logged and ignored). Log `FILTERED <n>` when n > 0.
   f. **Enrich by event_id alone.** For each remaining item call get_recent_messages with `{"channel": <channel_id>, "limit": 25}` once (bounded, failure logged and ignored). From a matching row copy each present field: media, msgtype, is_from_principal, is_implicitly_mentioned, reply_expected, is_from_agent, is_system. Row values override poll values, including text-only rows. Filament media bytes are fetched via the authenticated media endpoint by media.sh.
   g. **Tag and deliver, never filter for agent status or lack of mention.** Acquire reply.lock.d (25 tries); timeout logs DELIVER-LOCK-TIMEOUT, prints NO_WORK, exits 3. Under the lock prune numbered item files whose every message id is in replied.json or whose mtime is over 24 h old, without acking. Assign consecutive numbers from items/next, persist the advanced counter and write each item and the full envelope in items/wake.json; never clear outstanding files or reset next. Reserve each number before writing its item, so an interrupted delivery may leave gaps but never reuses numbers. Release the lock. Output a line per new item `ITEM <number> <item tags> channel=<channel_id> messages=<k> <union of message tags>`, then the full envelope with work equal to the new numbered items, then `ITEMS <count>`. Message-tag union uses the fixed order below. Log WORK with the first timestamp and item count, then WAKE-DELIVERED; exit 0. The per-run stdout copy cannot be overwritten by a later wake.

      Message tags, space-separated in this order (empty string when none): PRINCIPAL (sender equals owner_id in self.json or is_from_principal true), AGENT (sender_is_agent or is_from_agent true), SYSTEM (is_system true), MENTIONED (is_mention true), IMPLIED (is_implicitly_mentioned true), REPLY_EXPECTED (reply_expected true), NO_REPLY_EXPECTED (reply_expected false; absent yields neither). Without owner_id, only the explicit principal flag supplies PRINCIPAL. Item tags: BACKCHANNEL or ROOM, then ANSWER if any message has PRINCIPAL, MENTIONED, IMPLIED or REPLY_EXPECTED; otherwise QUIET. Both ANSWER and QUIET are delivered; the agent answers backchannels, answers ROOM ANSWER and acks ROOM QUIET.

      A redelivered outstanding item gets a new number. Whichever number is answered first posts; the other acks through the replied-ids guard. Overlap is not duplication: old ids 1,2 and new ids 2,3 can both post because 3 is new content. Withheld stdout loses no server work: unanswered items are redelivered on the next poll.
   h. Else if `truncated` true: continue at once. Else sleep `min(next_poll_ms/1000, remaining - 20)` if positive, continue.
7. Print `NO_WORK`, exit 3.

`SELF_ID`: read from `self.json` if present and younger than 24 h, else fetched once per run with `get_self` and written to `self.json` (`user_id`, `owner_id`, `display_name`). A `get_self` failure classified `auth`/`reserved` is handled as in 6b; `other` → use `self.json` if it exists at any age, else skip the self-based filter rules for this run.

## media.sh
Usage: `bash /workspace/filament/media.sh <mxc_url>`. Foreground (under 60 s). Downloads one attachment to `$STATE/media/<sha1 of the mxc url>.<ext>` where ext comes from the response `Content-Type` (png, jpg, gif, webp, pdf, txt, mp4, else `bin`), via `curl -sS -m 60 -o <path> "https://api.filament.dm/mcp/agents/media?mxc_url=<url-encoded>"`. Refuses files over 20 MB (checks `Content-Length` with a HEAD or `-w` after download; deletes and prints `TOO_LARGE`). Prints the absolute path on success, exit 0; prints `DOWNLOAD_FAILED <reason>` and exits 1 otherwise (never classified as auth: a bad download is not a revoked token). Files under `media/` older than 1 hour are deleted at the start of every listen.sh run.

## reply.sh
Usage: `bash /workspace/filament/reply.sh <item-number> <<'FILAMENT_REPLY_END'` … markdown body … `FILAMENT_REPLY_END`, or `bash /workspace/filament/reply.sh --ack <item-number>`. Run as a tracked background job. It posts (or acks) that one item, then `exec`s restart_listener.sh unless lineage rotation is due. The body is read from stdin as bytes, verbatim, trailing newline stripped; the item is read from `items/<n>.json`. Nothing from either is ever interpolated into shell.
1. Export FILAMENT_JOB_START as the current epoch if absent. Initialise the budget and rotate logs. Log REPLY-START item=<n>, then take reply.lock.d (150 tries at 0.2 s, up to 30 s; timeout logs LOCK-TIMEOUT and chains without recording).
2. Under that lock increment lineage.json.count, creating `{"started": now, "count": 1}` if absent. Read rotate_after: integer 2..200 or default 12. At count >= limit, kill any live listener with TERM, wait up to 10 s, then KILL and log LISTENER-KILLED. Log ROTATE count=<n>, release the lock, clean up, print `ROTATE <backstop.task id>` (NONE if absent), exit 3 with no chain. Leave the item file outstanding. Every subsequent reply invocation still rotates until a new direct launch resets the counter. A stale old-lineage reply can increment a new lineage once; accepted. The limit is only a proxy for Hark's unobserved repeated-call limit.
3. Still under the lock, validate the positive item number, existence and parsed item before planning. Invalid means BAD_ITEM; empty reply body means EMPTY_BODY; no non-empty string ids means NO-IDS. These paths log and chain without recording. Read body bytes verbatim, stripping exactly one trailing LF, preserving CRLF and additional whitespace. Non-UTF-8 bodies and invalid reply targets are BAD_ITEM. Corrupt replied state fails closed.
4. Hold the lock through the network call. If --ack or all ids are already recorded, record the ids (atomic temp+rename, last 500) then poll_work ack (`HARK_MCP_TIMEOUT=30s`), log ACKED rc=<rc>. Otherwise record ids first, call reply_with.tool with its args plus markdown_body (`HARK_MCP_TIMEOUT=60s`), log REPLIED rc=<rc>, capped result to reply.log and full result to last_result.json. Never retry, even on definite failure. Classify reply or ack failures; auth/reserved writes auth_failed. Timeouts also respect the inherited remaining budget.
5. Remove the numbered item while still holding the lock, then release it. A repeated call on the same removed number is BAD_ITEM.
6. Log RELAUNCHED, close opened descriptors, `exec bash "$STATE/restart_listener.sh"` with no arguments. FILAMENT_JOB_START survives exec and preserves the tracked job's deadline. A live listener yields CHAIN-ALREADY-LISTENING in timing.log and ALREADY_LISTENING as the last stdout line.

## restart_listener.sh
Usage: `bash /workspace/filament/restart_listener.sh [--replace|--stop]`. Run as a tracked background job, or exec'd by reply.sh. Serialise through restart.lock.d (100 tries, up to 20 s; timeout RESTART_BUSY, exit 3). A restart.pending PID record closes the release-before-exec window for concurrent restarts.
1. Initialise budget and rotate. If auth_failed exists, print its word and exit 2, except --stop still stops a paused listener.
2. Any live listener, regardless of age, means ALREADY_LISTENING, exit 3, unless --replace or --stop. An idempotent no-op preserves the active lineage counter.
3. --replace kills a live listener with TERM, waits up to 10 s, KILL if needed, logs LISTENER-KILLED <pid>, reclaims stale ownership, then launches. --stop uses the same kill path, prints STOPPED or NO_LISTENER, exit 0, and never launches or resets lineage.
4. Before an actual direct launch (FILAMENT_JOB_START absent), take reply.lock.d (25 tries), atomically reset lineage.json to `{"started": now, "count": 0}`, release it. All lineage reads and writes hold that lock. An exec chain (environment variable present) leaves lineage alone. Timeout or failed reset prints RESTART_BUSY and exits 3.
5. Publish restart.pending, release the restart lock and exec listen.sh, which publishes its own started time and clears the handover record.

## backstop.sh and the scheduled task

Scheduled every 10 minutes, bound to the Filament project. The exact four-step prompt and the project skill's exit table live in HARK.md. Install writes the returned id immediately to backstop.task. Chat restarts and ROTATE responses call scheduled_task run_now with that id. The backstop performs conditional recovery; agents can still fail to follow the rules.

- `bash /workspace/filament/backstop.sh check`: init_job, truncate backstop.log to its last 200 lines, then choose exactly one status. auth_failed exists: PAUSED. Otherwise a live listener with its newest POLL younger than 180 s or started younger than 180 s: RUNNING. Otherwise a live listener: WEDGED. No live listener: NEED_START. Append ISO 8601 date/time and status, print status, exit 0. Truncation precedes appending, so the resulting log can have 201 lines. Use dated POLL lines for unambiguous ages; accept legacy time-only lines across midnight.
- `backstop.sh started`: append ISO 8601 date/time and STARTED.
- `backstop.sh warn <percent> <resets_at>`: reject non-integer or out-of-range 0..100 percent as BAD_PERCENT, exit 1. If quota_warned is younger than 20 h, print ALREADY_WARNED, exit 0. Otherwise use run_mcp message_principal with exactly `Heads up: I have used <percent>% of today's Hark tokens. If I go quiet, that is why; the allowance resets at <resets_at>.`. Pass resets_at as literal argument data through the JSON helper. On rc 0 touch quota_warned. Print WARNED rc=<rc>, exit 0; never write auth_failed.
- Prompt: check; launch for NEED_START, --replace for WEDGED, then record started; call billing_status and warn at 85% or above; send no chat message. Subsequent wakes follow project skill rules.

## Tests (under tests/ in this worktree)

Run `bash tests/run.sh` from filament-hark/. Every scenario uses temporary FILAMENT_STATE, fake mcpcall and curl, real processes and epoch deadlines. FILAMENT_TEST_FAST=1 scales only sleeps/waits tenfold, not budget arithmetic or network delays. Bash 3.2 on macOS and Bash on Linux; no installs, flock or /proc. bash -n checks every production script and ShellCheck runs when installed. A test-only process catalogue is explicitly reported if the sandbox blocks native ps; that run does not establish native process-identity compatibility.

The full suite retains empty/second/truncated/busy polls, auth and reserved errors and false positives, concurrent listeners, stale locks, TERM and child reaping, byte-exact replies and record-before-send, duplicate/ack/invalid/failure paths, inherited deadlines, log rotation/caps, cache/invites, concurrent replies and record bounds, fail-closed corruption, media enrichment/download/cleanup and download limits. Updated filtering tests retain unmentioned agents and assert AGENT tags.

New coverage: ordered tags and text-only enrichment with row precedence; no-self principal flag; summary lines before JSON and final count; stable numbers across wakes and old targets; redelivery and overlap; pruning and counter preservation; live restart at any age, replace, stop and concurrent restart; counter reset, increments, limits, listener-killing ROTATE and later stragglers; dead/live/missing-pid reclaim and simultaneous claimants; all four backstop states, dated logs, truncation and started; exact quota body, 20 h throttle, validation, failure and literal shell-like text; first-poll readiness; media's rotation lock and delivery lock timeout. tests/README.md documents local and Hark runs.

## Cold-install acceptance checklist (manual, on Tony's Hark, before publishing)
Second agent created in the app; sentence pasted; token through the form; `get_self` right; avatar changed; project created and assigned; project fetched HARK.md and scripts, hashes matched; permission saved; listener up and matching LISTENER-READY pid logged within 90 s; project-doc skill saved; backstop task bound to the project and id saved; hello arrived in the backchannel; a message answered within 15 s; a second message answered once; `NO_WORK` relaunch observed; backstop RUNNING twice; WEDGED replacement and ROTATE run_now observed; a cold scheduled wake answers principal backchannel work and acks ROOM QUIET; nothing about Filament in the main chat after the handoff line.

## Out of scope for v1
Avatar cropping, search before answering, FCM, more than one connector per account. The Muse connector has the first two and they port once the cold install works.
